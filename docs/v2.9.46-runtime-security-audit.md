# DARK NOC v2.9.46 Runtime Security Audit

This release hardens authenticated browser and SSH control-plane surfaces while keeping existing deployment and tunnel behavior compatible.

## Security changes

- Unsafe browser API requests are restricted to the configured same origin.
- Live and SSH WebSockets validate browser Origin before accepting authenticated cookies.
- Interactive SSH WebSocket messages, terminal input and resize values are bounded.
- Session cookies use explicit Path, HttpOnly and SameSite=Strict settings with HTTPS-aware Secure handling.
- Expired sessions are cleaned during successful/failed login processing without nested SQLite writers.
- Authenticated API responses are marked no-store/no-cache and receive same-origin opener/resource policy headers.
- File Manager destructive writes resolve remote parent paths through SFTP and reject protected destinations reached through symlinks.
- SSH host-key pinning, persistent tmux sessions and existing browser terminal protocol are preserved.

## Plugin Contract hardening

- Each native plugin manifest owns a validated `runtime.service_prefix`.
- Hub Agent telemetry acceptance is derived from the manifest catalog instead of a four-plugin hardcoded allowlist.
- Plugin transport/profile request fields accept bounded safe identifiers and are validated against the selected plugin manifest at the service layer.
- Hub manifests and Agent adapters remain covered by the Plugin Registry drift contract.

## Validation

The candidate passed the complete DARK NOC regression suite, the Runtime Security contract, Plugin Registry contract, installer/upgrade contracts, Realm tests, SSH/File Manager tests, dependency contracts and a reproducible HUB/NODE release build before promotion to the clean release branch.
